## 行为范围

最终报告 JSON envelope 只用于 `SQLNodes.summarize` 的最终总结调用。普通决定节点 `SQLNodes.decide` 仍读取 content-only 响应；分类、普通决定、历史压缩和执行步骤压缩继续使用原有格式与调用控制。

报告解码器校验单一 JSON envelope、必要字段、字面量 `complete: true`、Markdown 正文、结束标记和实际 provider finish reason。`complete: true` 仅是报告传输格式中的必需标志；结构完整或 provider 正常结束都不证明报告事实正确、SQL 结果正确或用户任务已经完成。事实和任务结果仍须依据工具记录、数据结果及人工答案复核。

缺失的 finish reason 保持未知；长度截断、内容过滤、意外工具调用或被识别的工具协议会使最终报告不被接受。只在最终报告路径检查协议 framing，不改变普通 content-only 决定的既有清理与工具恢复规则。

实现不会新增模型调用、自动生成重试、重放工具调用或重放 SQL/DDL/写操作。若最终报告不完整，系统沿用现有错误和结束路径返回七语安全提示；已完成的写入不会因报告失败而回滚，`completedWriteCount` 保留。用户再次发送前应先检查先前已执行步骤，避免重复执行。

成功与失败都沿用既有 SSE 事件和 Usage 字段，不新增公开事件或用量字段。最终 Markdown 仍通过原摘要流交付；内部观测记录安全长度、SHA 与枚举，原有一次性用量记账、取消和 finally 清理保持。传输中断不能被提升为完整报告证据。
